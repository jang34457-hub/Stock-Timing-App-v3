# Stock Timing App 개발계획서 V3.0

## 1. 프로젝트 목표

**Stock Timing**은 KOSPI·KOSDAQ 종목 중 거래대금이 많은 종목을 자동으로 선정하고, 사용자가 관심종목으로 지정한 종목에 대해 **3일 이동평균선(MA3)을 이용해 매수·매도 추천 신호를 알려주는 모바일 앱**입니다.

핵심은 AI가 주가를 예측하는 것이 아니라, **정해진 수학적 규칙을 서버가 자동 계산하고, 조건이 충족되면 SMS로 알려주는 시스템**으로 먼저 만드는 것입니다.

이번 프로젝트에서는 **Antigravity 대신 Cursor**를 사용합니다.

초보 단계에서는 Cursor가 코드 작성뿐 아니라 파일 구조를 이해하고 기존 코드를 수정하는 과정에서 사용하기 편리합니다.

### 추천 구성

| 영역 | 기술 |

## 4. 가장 중요한 개발 원칙

이번 프로젝트에서는 다음 원칙을 지킵니다.

1. **LLM에게 주가 계산을 시키지 않는다.**
2. **주식 데이터 API에서 이미 받은 데이터를 다시 받지 않는다.**
3. **TOP20이 아닌 종목의 일별 주가 데이터는 기본적으로 수집하지 않는다.**
4. **앱이 실행되지 않아도 서버에서 자동으로 처리한다.**
5. **6개월 차트와 3개월 신호 분석을 분리한다.**

이 다섯 가지가 이번 앱의 핵심입니다.

## 5. TOP20 선정 방법

KOSPI + KOSDAQ 전체 종목을 대상으로 합니다.

기준은 **최근 3개월 일평균 거래대금**입니다.

계산식:

```
최근 3개월 일평균 거래대금
= 최근 3개월 거래대금 합계 ÷ 실제 거래일 수
```

높은 순서대로 정렬하여 1위 ~ 20위를 선정합니다.

## 6. TOP20 선정 주기

매일 선정하지 않습니다.

기본 일정은 **매주 월요일 장 마감 후** TOP20을 다시 선정하는 것입니다.

```
월요일 정상 거래
       ↓
월요일 장 마감 후 선정

월요일 휴장
       ↓
다음 거래일 장 마감 후 선정
```

따라서 스케줄러에는 단순히 "매주 월요일"이라고 하드코딩하지 않고, **"해당 주의 첫 거래일인지 확인"**하는 로직을 넣겠습니다.

## 7. TOP20 선정에서 API 호출을 줄이는 방법

여기가 매우 중요합니다.

매주 KOSPI/KOSDAQ 전체 종목의 3개월 데이터를 모두 다시 가져오면 API 호출량이 많아집니다.

따라서 **거래대금 데이터도 DB에 축적**합니다.

예를 들어 `trading_daily`에 다음을 저장합니다.

- 종목코드
- 날짜
- 거래대금

그러면 매주 월요일에는:

```
DB에 이미 저장된 최근 3개월 거래대금
        +
새로운 거래일 데이터
        ↓
3개월 평균 재계산
        ↓
TOP20 선정
```

이 가능합니다.

즉, **과거 데이터를 매주 다시 다운로드하지 않습니다.**

## 8. 주가 데이터 증분 업데이트

이번 프로젝트의 핵심 기능입니다.

### 최초 등록

새로운 TOP20 종목이 등장하면 **최근 6개월 데이터가 DB에 있는가?**를 확인합니다.

없다면:

```
필요한 기간만 API 호출
        ↓
6개월 데이터 확보
        ↓
DB 저장
```

### 이후 매일

예를 들어 DB가 `2026-09-04`까지 저장되어 있다면, 9월 7일 장 마감 후에는:

```
DB 마지막 날짜 = 9/4
        ↓
API 요청: 9/5 이후 데이터
        ↓
9/7 데이터 저장
```

**이미 저장된 6개월 데이터를 다시 요청하지 않습니다.**

## 9. 더 효율적인 증분 업데이트 구조

단순히 "마지막 날짜 이후 데이터를 가져온다"보다 한 단계 더 안전하게 설계합니다.

서버가 API를 호출하기 전에:

1. DB에서 마지막 거래일 확인
2. 거래 캘린더 확인
3. 필요한 날짜 범위 계산
4. API 호출
5. 이미 존재하는 데이터는 UPSERT

방식으로 처리합니다.

예:

```
DB: 9/1, 9/2, 9/3, 9/4, 9/7
API: 9/8만 요청
```

만약 API 오류로 9/7 데이터가 빠져 있다면:

```
DB: 9/1 ~ 9/6
API: 9/7 ~ 오늘
```

을 가져옵니다.

즉 **중간에 빠진 날짜도 자동 보완**할 수 있게 합니다.

## 10. 6개월 차트 vs 3개월 분석

이번에 아주 중요한 조건을 명확히 분리합니다.

### 차트 표시

**최근 6개월**

```
<──────────── 6개월 ────────────>
종가
MA3
```

전체를 보여줍니다.

### 신호 계산

**최근 3개월**

```
<────── 3개월 ──────>
MA3 최고점
MA3 최저점
      ↓
X1 / X2
Y1 / Y2
```

만 사용합니다.

즉: **DB와 차트에는 6개월을 보관하지만, 매수·매도 기준점 계산에는 최근 3개월만 사용합니다.**

## 11. MA3 계산

모든 TOP20 종목에 대해:

```
MA3 = (오늘 종가 + 전일 종가 + 전전일 종가) / 3
```

를 계산합니다.

이것은 LLM을 전혀 사용할 필요가 없습니다. **Python 코드로 계산**합니다.

## 12. 최고점/최저점 정의

이번 버전에서 확정합니다.

- **최고점**: 최근 3개월의 **MA3 중 최고값**
- **최저점**: 최근 3개월의 **MA3 중 최저값**

즉,

- ❌ 최근 3개월 종가 최고가
- ❌ 최근 3개월 종가 최저가
- ⭕ 최근 3개월 MA3 최고값
- ⭕ 최근 3개월 MA3 최저값

입니다.

## 13. 매도 신호

기본값:

- `X1 = 10%`
- `X2 = 20%`

최근 3개월 MA3 최고값을 `H`라고 하면:

```
매도1 기준 = H × (1 - X1/100)
매도2 기준 = H × (1 - X2/100)
```

예: MA3 최고점 = 100,000원

- `X1 = 10%` → 90,000원
- `X2 = 20%` → 80,000원

## 14. 매수 신호

기본값:

- `Y1 = 10%`
- `Y2 = 20%`

최근 3개월 MA3 최저값을 `L`이라고 하면:

```
매수1 기준 = L × (1 + Y1/100)
매수2 기준 = L × (1 + Y2/100)
```

예: MA3 최저점 = 50,000원

- `Y1 = 10%` → 55,000원
- `Y2 = 20%` → 60,000원

## 15. 신호는 "돌파"일 때만 발생

매우 중요합니다.

예를 들어 매도1 기준이 90,000원인데:

```
9/7 MA3 = 89,000
9/8 MA3 = 88,000
9/9 MA3 = 87,000
```

이라고 해서 매일 문자를 보내면 안 됩니다.

**처음 기준선을 돌파하는 순간만 이벤트로 처리합니다.**

매도:

```
전일 MA3 > 기준가격
AND
오늘 MA3 <= 기준가격
        ↓
매도 신호
```

매수는 반대로:

```
전일 MA3 < 기준가격
AND
오늘 MA3 >= 기준가격
        ↓
매수 신호
```

입니다.

## 17. SMS 발송 원칙

**관심종목으로 선택한 종목에 대해서만 SMS를 발송합니다.**

예를 들어 TOP20 = 20개, 관심종목 = 5개라면 신호 알림은 **5개 종목만 대상**입니다.

이를 통해 SMS 비용도 절약할 수 있습니다.

## 18. 앱을 꺼놓아도 작동하는 구조

이 부분 때문에 서버 자동화가 필요합니다.

사용자가 앱 종료, 휴대폰 잠금 상태여도 상관없습니다.

서버가:

```
장 마감
   ↓
자동 실행
   ↓
가격 업데이트
   ↓
MA3
   ↓
신호 계산
   ↓
관심종목 확인
   ↓
SMS
```

를 수행합니다.

## 19. 하루 한 번만 업데이트

초기 MVP에서는 **장중 실시간 데이터는 사용하지 않습니다.**

매일 장 마감 후 1회만 처리합니다.

예:

```
15:30 장 마감
      ↓
데이터 처리
      ↓
16:00 전후 SMS
```

실제 시간은 API와 서버 환경에 맞춰 조정합니다.

## 20. 데이터 처리량을 줄이는 핵심 구조

여기서 중요한 최적화가 하나 더 있습니다.

**TOP20 전체를 대상으로 MA3를 매번 다시 계산하지 않고, 새로 들어온 데이터에 대해서만 계산**하도록 합니다.

예를 들어 기존 DB에 9/1 MA3, 9/2 MA3, …, 9/4 MA3가 있다면, 오늘 9/7 데이터가 들어오면 9/5, 9/7 등 누락된 날짜를 처리하면서 필요한 MA3만 추가 계산합니다.

다만 신호 계산에서는 최근 3개월의 최고/최저값을 확인해야 하므로 **최근 3개월 MA3 데이터만 DB에서 조회**하면 됩니다.

## 23. API 호출 최적화 전략

최종적으로 다음 6가지 원칙을 적용합니다.

1. **TOP20 선정은 주 1회** — 불필요한 매일 계산 제거.
2. **가격 데이터는 TOP20만** — 전체 종목의 매일 가격을 가져오지 않음.
3. **6개월 최초 1회 확보** — 신규 종목만 과거 데이터 확보.
4. **이후 증분 업데이트** — 마지막 DB 날짜 이후만 요청.
5. **누락 데이터만 보완** — 이미 존재하는 날짜는 다시 받지 않음.
6. **LLM을 데이터 처리에서 제외** — 주가 계산은 Python.

이렇게 하면 **LLM 토큰 사용량은 극소화**할 수 있습니다.

## 24. LLM 토큰 사용량 최적화

Cursor를 사용한다고 해서 모든 작업을 AI에게 시킬 필요는 없습니다.

### AI에게 맡길 것

- 코드 생성
- 코드 설명
- 오류 분석
- DB 설계 검토
- UI 구현
- API 연동 코드 작성

### AI에게 맡기지 않을 것

- 주가 데이터 수집
- MA3 계산
- 거래대금 계산
- TOP20 계산
- 매수/매도 신호 계산
- DB 조회
- SMS 발송

이것들은 모두 **프로그램 코드가 직접 수행**하도록 합니다.

## 25. Cursor 사용 방법

초보 단계라는 점을 고려해서 **한 번에 전체 프로젝트를 만들지 않습니다.**

Cursor에게 `"Stock Timing 앱을 만들어줘."`라고 하지 않는 것이 좋습니다.

대신 아래 순서대로 진행합니다.

```
STEP 1  Supabase DB 설계

STEP 2  Python 데이터 수집 모듈
  ↓
STEP 3  TOP20 계산
  ↓
STEP 4  증분 업데이트
  ↓
STEP 5  MA3
  ↓
STEP 6  신호 알고리즘
  ↓
STEP 7  FastAPI
  ↓
STEP 8  React Native
  ...
```

## 26. 실제 개발 순서

### STEP 1 — 프로젝트 생성

Cursor에서 `Stock-Timing-App` 프로젝트를 생성합니다.

구조:

```
Stock-Timing-App/
├─ backend/
├─ frontend/
├─ database/
├─ scripts/
├─ docs/
└─ README.md
```

GitHub와 연결합니다.

### STEP 2 — Supabase

먼저 DB부터 만듭니다.

테이블:

- `stocks`
- `daily_prices`
- `top20_history`
- `user_settings`
- `user_watchlist`
- `signal_history`

그리고 기본적인 **RLS(Row Level Security)** 정책을 설정합니다.

### STEP 3 — 주식 데이터 API

이 단계에서는 아직 모바일 앱을 만들지 않습니다.

Python에서 다음이 제대로 작동하는지 확인합니다.

- 종목 목록 가져오기
- 가격 가져오기
- 거래대금 가져오기

### STEP 4 — TOP20 엔진

Python으로:

```
KOSPI + KOSDAQ
        ↓
3개월 거래대금
        ↓
일평균
        ↓
정렬
        ↓
TOP20
```

을 구현합니다.

### STEP 5 — 증분 업데이트 엔진

이 단계가 매우 중요합니다.

다음 함수를 만드는 것을 추천합니다.

- `get_last_date(stock_code)`
- `get_missing_dates(stock_code)`
- `fetch_missing_prices(stock_code)`
- `save_prices()`
- `update_ma3()`

이렇게 모듈화하면 나중에 오류가 발생해도 어디를 고쳐야 하는지 명확합니다.

### STEP 6 — MA3 엔진

## 이번 프로젝트에서 가장 중요한 설계 5가지

최종적으로 다음과 같이 확정하면 됩니다.

1. **TOP20은 KOSPI+KOSDAQ 중 최근 3개월 일평균 거래대금 기준으로 매주 월요일 장 마감 후 선정**
2. **TOP20 종목만 가격 데이터를 수집하며, 기존 DB 데이터는 다시 API에서 가져오지 않고 누락분만 증분 업데이트**
3. **차트는 최근 6개월을 보여주지만, 최고점·최저점·매수·매도 신호 계산은 최근 3개월 MA3만 사용**
4. **사용자가 선택한 관심종목에 대해서만 매수·매도 SMS 발송**
5. **Cursor + React Native/Expo + Python/FastAPI + Supabase + Lightweight Charts를 사용하고, LLM은 코딩 보조에만 제한적으로 사용**

이 구조라면 **초보 단계에서도 한 단계씩 만들어가면서 각 단계가 정상 작동하는지 확인할 수 있고**, 동시에 불필요한 주식 API 호출과 LLM 토큰 사용을 상당히 줄일 수 있습니다.

**다음 실제 작업은 STEP 1: Supabase 데이터베이스 설계부터 시작하는 것이 가장 좋습니다.** 다음 단계에서는 Supabase에서 만들 테이블 6개의 정확한 필드명·데이터형식·Primary Key·Index·Foreign Key·RLS 정책까지 포함한 DB 설계서를 만들고, 이어서 Cursor에 복사해서 넣을 STEP 1 개발 프롬프트까지 작성하는 방식으로 진행하면 됩니다.
